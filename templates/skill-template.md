# Skill 模板说明（A 模式，2026-08-03 定稿）

> 生成新 skill 的完整蓝图：三件事分层 + 文件层级 + 参考分层 + 生成判据。
> 用法：加载 agent-skill-gen 后，按本模板设计新 skill 的文件构成，与用户确认后创建。
> 定位：模板 = 可替换的参考实现——约束流程行为，不约束细节。

## 一、总览：先定三件事，再派生支持文件

| 概念 | 问题 | 物化位置 |
|------|------|---------|
| SKILL.md | 怎么做（主流程操作手册） | skill 根，唯一必需，唯一入口 |
| 资产侧宪法 | 做成什么样（目标态） | 被管理资产内（真相源）；skill 侧 init 快照放根目录平级 |
| CHANGELOG.md | 发生过什么（版本记录） | skill 根 |

**组织顺序**：宪法（做成什么样）在前、流程（怎么做）在后——但这是文档组织顺序，不是知识诞生顺序（实践驱动型技能常先有实践后提炼宪法）。

支持文件从三件事派生，**每个文件必须回答「支撑谁 / 何时查」，回答不上不建**：

| 支持文件 | 溯源 | 何时查 |
|---------|------|-------|
| templates/ | 做成什么样（实例化骨架） | 初始化/产内容时 |
| references/ · 坑 | 怎么做（反面边界） | 遇到问题时 |
| references/ · 决策原因 | 怎么做（为什么） | 需要理解时 |
| references/ · 接入参考 | 怎么做（接口） | 下级接入时 |
| scripts/ | 怎么做（自动化） | 执行任务时 |

## 二、目录结构（空骨架）

```
<skill>/
├── SKILL.md          ← 怎么做（操作流程）——唯一必需，唯一入口
├── SCHEMA.md         ← 做成什么样（可选）：与 SKILL.md 概念平级的宪法/蓝图——物理并列，唯一真相源随 skill 分发，资产内不放置实例
├── CHANGELOG.md      ← 发生过什么（版本历史，随安装拷贝）
├── templates/        ← 生成骨架（准入标准 = 可替换性：可替换的参考实现；不可替换的约定内容不放这里）
├── references/       ← 参考层：坑（遇问题排障）+ 决策原因（为什么这样）+ 接入参考——SKILL.md 保持干净主流程
├── scripts/          ← 可执行脚本（agent 专用，无终端直连通道）
└── assets/           ← 资源（可选）
```

## 三、SCHEMA.md — 做成什么样（资产侧宪法）

**必要性判据**：管理**持续演进的被管理资产**（会增长/过时/矛盾的文档库，如知识库/任务体系）→ 需要宪法，不管多简单（篇幅可小，七节按需取舍）；纯操作/无资产技能（刷机/测试/部署）→ 不需要，其"做成什么样"以内嵌验收标准留在 SKILL.md（如烧录成功信号），不建独立宪法。**判据是"是否有资产"，不是"技能复杂程度"。**

**定位**：定义被管理资产的目标态——目录结构/命名/纯度/文档公约/演进规则。与 SKILL.md 概念平级（做成什么样 vs 怎么做），物理并列放根目录；**唯一真相源在本 skill**（随 skill 分发），资产内不放置实例——init 不生成宪法实例（qwiki v2.0.0：实例 = 第三层 copy，双头维护漂移）。

**必备七节**（qwiki 验证的框架，按资产类型取舍）：

| 节 | 回答 | 示例内容 |
|----|------|---------|
| 定位声明 | 本文与 SKILL 的关系 | SCHEMA = 做成什么样；SKILL = 怎么做。平级互补 |
| 目录结构 | 资产物理骨架长什么样 | ascii tree + 每行注释 |
| 命名约定 | 目录/文件名规则 | 全小写连字符；项目内文件保留原名 |
| 内容纯度 | 什么进、什么不进、冲突怎么办 | 放：已验证知识/决策/复盘；不放：临时笔记/未验证猜想/代码本身；新旧矛盾两边都记 + 打标记 |
| 文档公约 | 文档长什么样 | YAML 头（必填项/真相源字段）+ 最小单元（卡片身份）+ 互联规则（双链） |
| 演进规则 | 内容怎么活 | 活知识原则：过时修正/销毁 + 防腐化判定（死链修引用/矛盾修正/过时销毁/孤岛保留） |
| 迁移规则 | 层级间怎么流动 | L2→L1 方向；只进不出仅限档案类，卡片可修正销毁 |

**写法要点**：
- 宪法是约定本身，不可替换 → 根目录平级，不进 templates/
- 一句一个规则，不留解释性散文（解释归 references/ 决策原因）
- 模板 ↔ 实例：模板更新 ≠ 实例自动跟随，关键语义变更必须手动同步
- 不写操作步骤（那是 SKILL.md 的事）——宪法只定义目标态，SKILL 实现它

## 四、SKILL.md — 怎么做（主流程操作手册）

必填内容（按序）：

1. **frontmatter**：name（动词-名词，查占用）/ description（前 57 字符内自含触发条件）/ version（单一真相源）/ category / metadata.triggers
2. **AI 使用哲学头节**：顶部声明「用户指挥 AI，AI 替用户执行」+ 执行路径示例 + 铁律（给出意图就干不反问）+ AI 交互约定
3. **操作路由表**：输入 → 操作 → 参数（qwiki 式）
4. **操作流程**：步骤化，每操作一节
5. **支持文件清单**：末尾反引号引用全部支持文件（`_referenced_support_paths` 校验，缺引用 = install 漏装）

不承载（A 模式）：
- 坑/排障经验 → references/（高频坑也不例外——分层一致性 > 少翻一层）
- 决策原因 → references/
- 详细调试笔记 → references/（本地，不发布）

## 五、references/ — 参考层（A 模式）

三类参考，定位标清：

| 类型 | 内容 | 定位 |
|------|------|------|
| 坑 | 排障经验/反模式/失败教训 | 遇问题按需查（排障参考） |
| 决策原因 | 为什么这样设计/方案取舍 | 理解需要时查（理解参考） |
| 接入参考 | 下级如何接入本技能/接口约定 | 接入时查（接口参考） |

- **参考层不是档案层**：服务未来查询（遇到问题/需要理解时），记录过去归 CHANGELOG
- **发布边界**：可泛化的坑/决策原因随包发布；项目特定调试笔记/单次分析不发布（无对外价值 + 敏感重灾区，脱敏成本高）
- **引用要清理**：保知识去链接——正文保留知识，删「详见 references/xxx.md」尾巴

## 六、templates/ — 实例化骨架

- 准入标准 = **可替换性**：可替换的参考实现（约束流程行为，不约束细节）
- 不可替换的约定/宪法内容不放这里——与 SKILL.md 概念平级的放根目录（概念平级必须物理平级）
- 两类模板：
  - init 类：建库/建资产骨架用，进 init 流程（如 index.md/history.md）
  - 生成类：产内容用（如 card.md/note.md）
- 模板不做组合（基板模板 = 死文件），继承靠内嵌 + 引用

## 七、scripts/ — 可执行脚本

- **agent 专用，无终端交互通道**：脚本面向 AI 调用（`--xxx` 参数路径），不提供真人终端向导交互；非 TTY（AI/管道）提示参数路径退出，不傻等 stdin
- 向导先收集后写盘、取消零副作用
- 脚本必须被 SKILL.md 反引号引用（否则 install 漏装）
- 发布前 `python3 -m py_compile` 全过

## 八、版本化

- version 单一真相源：SKILL.md frontmatter，CHANGELOG/install.sh 都读它
- CHANGELOG 只承载版本记录，不兼任决策档案（决策原因去 references）
- 对外分发加 install.sh：版本对比 + 旧版 .bak + 拷贝 CHANGELOG

## 九、生成判据（创建前自查）

1. 三件事都定了吗？（怎么做 / 做成什么样 / 发生过什么）
2. 每个支持文件能回答「支撑谁 / 何时查」吗？回答不上 → 不建
3. 与 SKILL.md 概念平级的文档物理平级了吗？（根目录，不在 templates/references）
4. templates/ 里全是可替换的参考实现吗？
5. SKILL.md 干净吗？（无坑、无决策原因、无调试笔记）
6. 支持文件清单全引用了吗？
7. 有持续演进资产吗？有 → SCHEMA 七节框架齐了吗（只定义目标态，不写操作步骤）；无 → 不建 SCHEMA，验收标准内嵌 SKILL.md
